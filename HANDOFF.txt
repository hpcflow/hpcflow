FEATURE CONTRACT

SchemaOutput accepts multiplicity as a positive integer, default 1. The argument
follows propagation_mode, preserving existing positional propagation-mode calls:
  hf.SchemaOutput("p2", multiplicity=3)

Multiplicity is the number of sourceable output members PER upstream element,
not the number of upstream elements. Two upstream elements producing [10, 11, 12]
and [20, 21, 22], each with multiplicity=3, supply six downstream input candidates
in element order followed by member order.

Actions still write the whole output. For multiplicity > 1, it must be a list,
tuple or NumPy array of the declared length. Length is checked when a downstream
member is read. Multiplicity omitted or equal to 1 supplies the whole output
unchanged, including when it is itself a list. Booleans/non-integers raise
TypeError; zero/negative integers raise ValueError.

Python/YAML definitions, schema serialization, and JSON/Zarr workflow reloads
preserve multiplicity; legacy definitions default to 1. Existing source precedence,
propagation rules, labels, element selection, grouping and nesting remain in use.
